# 핵심 노트 설계 (1단계: 글 노트)

작성일: 2026-10-08 · 앞선 설계: `2026-10-08-fsrs-design.md`. 사진·지도는 2단계(별도 설계)로 미룬다.

## 목표

카드만으로는 흐름·인과가 안 잡히고, 비슷한 것끼리 섞인다. 카드와 연결된 핵심 노트로 네 가지를 돕는다.

1. **카드 전에 흐름 이해** — 시대의 큰 틀과 인과를 먼저 잡고 카드로 외운다.
2. **틀린 카드에서 펼쳐 보기** — 오답 직후 그 카드가 속한 노트 항목으로 바로 간다.
3. **시험 직전 훑어보기** — 한 줄 핵심만 빠르게, 기억률 낮은 항목 먼저.
4. **헷갈리는 것 정리** — 시대별 비교표.

성공 기준: 모든 카드가 노트 항목에 연결되고, 노트 항목에서 바로 그 카드를 풀 수 있고, 노트의 모든 사실이 사실 확인을 통과한다.

## 학습 원리 → 설계

| 원리 | 반영 |
|---|---|
| 선행 조직자(큰 틀 먼저) | 시대 맨 위 `흐름` 3~6단계 |
| 정교화·인과 | 항목의 `why`(왜 그렇게 됐나) |
| 청킹 | 시대 → 주제 → 항목, 항목당 카드 5~8장 안팎 |
| 변별 학습 | `confuse`(헷갈리는 짝), "헷갈리는 것" 주제의 비교표 |
| 인출 연습(읽기보다 강함) | "가리고 떠올리기", 항목에서 바로 카드 풀기 |
| 암기법 | 순서·목록처럼 이해로 안 풀리는 곳에만 `memo` |

## 화면

- 홈: "핵심 노트" 버튼 → 시대 목록 → 시대 노트.
- 시대 노트:
  - 맨 위 `흐름`(화살표로 이은 단계).
  - 주제별 항목 목록. 접힌 상태 = `head — key` 한 줄 + 오른쪽에 연결 카드 기억률 평균 %(안 본 카드는 0).
  - 펼치면(`<details>`) `why`, ⚠ `confuse`, 🔑 `memo`, 비교표(`table`), 버튼 "이 항목 카드 N장 풀기".
  - 상단 토글 "가리고 떠올리기": 켜면 `key`가 "?"로 가려지고, 누르면 보인다. 토글 상태는 localStorage(실패해도 기본값으로 동작).
- 문제 화면: 답한 뒤 그 카드가 연결된 항목이 있으면 "노트 보기" → 해당 항목을 펼친 노트로 이동, 뒤로 가기로 풀던 문제로 복귀.
- 카드 풀기(모드 `note`): 그 항목 카드만, 오늘 복습 → 새 카드 → 미리 복습 순서로 7장씩. 이번 라운드에 푼 카드는 제외, 다 풀면 라운드 끝(자주 틀린 카드 모드와 같은 방식). 채점·복습 기록은 다른 모드와 동일(FSRS).
- 하지 않는 것: 노트 읽음 기록, 메모·형광펜, 사진·지도(2단계).

## 데이터

`notes.json` = 시대 배열(ERAS 순서, 기타 제외).

```json
{ "era": "고려",
  "flow": ["호족 연합", "문벌 귀족", "무신 정권", "원 간섭", "신진 사대부·멸망"],
  "topics": [
    { "title": "왕과 체제 정비", "items": [
      { "id": "goryeo-seongjong", "head": "성종", "key": "유교 정치 기틀 (시무 28조·12목)",
        "why": "…", "confuse": "12목(성종) ↔ 5도 양계(현종)", "cards": ["c0003", "…"] } ] } ] }
```

- 항목 필드: `id`(영문 소문자·숫자·하이픈, 전체에서 유일) · `head`(이름) · `key`(한 줄 핵심, 40자 이내) · `why`(1~3문장, 150자 이내) · `confuse`?(60자 이내) · `memo`?(60자 이내) · `table`?(행 배열, 첫 행 머리글, 모든 행 같은 칸 수) · `cards`(카드 id 1개 이상).
- 시대마다 마지막 주제는 "헷갈리는 것"(비교표 항목 모음).
- **모든 카드는 하나 이상의 항목에 연결**한다. 카드가 여러 항목에 있으면 "노트 보기"는 문서 순서상 첫 항목.
- 앱은 `cards.json`과 함께 `notes.json`을 불러오고, 카드 → 항목 역색인을 만든다. 불러오기 실패 시 노트 버튼만 숨기고 나머지는 정상 동작.
- `sw.js` FILES에 `notes.json` 추가.

## 내용 작성

- 출처: 감수를 마친 `cards.json`이 사실 기준이다. 노트는 카드 사실을 묶고 인과를 덧붙인다. 카드에 없는 사실을 쓸 때는 교과서 수준에서 확실한 것만.
- 모든 문장은 직접 쓴다(교재·기출 문장 인용 금지).
- 시대별로 나눠 병렬 작성(카드 감수 때와 같은 방식): 시대의 카드 전체와 기출 분석(`docs/content/gichul/*.json`)을 읽고, 흐름 → 주제 → 항목을 짜고, 모든 카드를 항목에 배정한다. 항목은 주제 안에서 시간순.
- 분량 목표: 시대당 항목 = 카드 수 / 7 안팎(전체 약 550개), `key`는 시험에 나오는 키워드 위주.
- 작성 후 별도 사실 확인 단계: `key`·`why`·`confuse`·`memo`·`table`의 모든 사실을 검증하고, 틀린 것은 고친다.
