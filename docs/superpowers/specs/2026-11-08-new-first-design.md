# 새 카드 먼저, 틀린 카드 복습 다음 (v24)

작성일: 2026-11-08 · 앞선 설계: `2026-11-07-exam-plan-design.md`.

## 왜

- 학습자의 요청: "새 카드를 먼저 한 바퀴 돌리고, 거기서 틀린 문제를 우선으로."
- 이전 순서는 오늘 복습 → 새 카드 → 미리 복습이었어요. FSRS 90%는 복습 날이 된 카드를 모두 먼저 냈고, 시험이 3주 앞이면 시간이 복습에 묶여 새 카드를 다 보지 못했어요.

## 시뮬레이션 (11/8 → 11/28, 기본 1,773장, 57~79회 문항, FSRS를 기억의 참값으로)

- 비교한 순서
  - 현재: 복습 → 새 카드
  - 한 바퀴: 새 카드 전부 먼저, 복습은 남는 시간
  - 오늘 새 카드: 오늘 목표만큼 새 카드 → 틀린 복습 → 맞힌 복습
- 하루 시간은 평일 3·주말 6시간이고, 실전 날은 2시간을 뺐어요. 마지막 7일은 모두 마무리 학습(finalBatch)을 했어요. 시드 5개의 평균이에요.

| 처음 볼 때 아는 비율 · 공부 시간 | 현재 | 한 바퀴 | 오늘 새 카드 |
|---|---|---|---|
| 10% · 계획대로 | 86.6 (1,130장) | 91.5 (1,773) | 91.4 (1,773) |
| 30% · 계획대로 | 88.6 (1,226) | 93.8 | 94.6 |
| 60% · 계획대로 | 91.3 (1,396) | 97.1 | 97.3 |
| 30% · 계획의 60% | 73.1 (740) | 79.3 (1,216) | 79.3 (1,216) |

- 새 카드를 먼저 하면 모든 경우에 5~6점 높았어요. 시험이 가까우면 외운 카드를 90%로 지키는 것보다 한 번이라도 보는 쪽이 커요.
- 대가는 밀린 복습이에요. 11/20에 복습할 날이 지난 카드가 1,600장쯤 쌓여요. 마무리 주간에 시험날 기준으로 정리하는 걸 전제로 한 결과예요.
- '한 바퀴'와 '오늘 새 카드'는 점수가 같았어요. 하루 목표를 지키는 쪽을 택했어요. 계획과 맞고, 틀린 카드가 날마다 다시 나오기 때문이에요.

## 바꾼 것

- `buildBatch(..., { newFirst })`
  - 순서: 새 카드 newFirst장 → 복습(틀린 적 있고 완료 전인 카드 먼저, 각각 잊은 순) → 나머지 새 카드 → 미리 복습.
  - 틀린 카드 먼저는 newFirst가 0이어도 적용돼요.
  - 한 묶음에 같은 대상은 하나만 넣는 규칙은 그대로라서, 같은 대상의 새 카드는 다음 묶음으로 밀릴 수 있어요.
- 학습 시작(1단계): newFirst = 오늘 계획의 새 카드 − 오늘 배운 새 카드. 시험일이 없거나 마무리 주간이면 0이에요(마무리 주간은 finalBatch).
- `studyPlan`: 새 카드가 먼저라 fit = 1단계 자유 시간 ÷ 1.25분이에요. 해설과 틀렸을 때 다시 푸는 시간을 포함했어요. 복습 시간을 빼던 `seen` 인자는 없앴어요.
- 홈 '오늘 할 일': 1. 새 카드 → 2. 틀린 적 있는 카드 복습 → 3. 나머지 복습("시간 남으면, 못 해도 마무리 주간에 다시 봐요").
- 가이드와 시험 계획의 근거에 바뀐 순서와 시뮬레이션 숫자를 넣었어요.
- 시기 맞히기·보기 판별·기출형·라운드 풀기는 newFirst 없이 예전 순서예요(복습 안에서는 틀린 카드가 먼저).

## 테스트

- 로직: newFirst 0·2·전부일 때의 순서, 완료된 카드는 '틀린 카드'로 치지 않음, studyPlan fit(1,773장은 모두 들어감, 3,000장이면 2,400), 주말에 필요한 시간.
- 화면(390px): 오늘 할 일 1·2·3 줄, 오늘 목표 전에는 묶음 전체가 새 카드, 목표 직전에는 남은 새 카드 다음 틀린 카드 복습. 콘솔 오류 0.

## 풀이 기록과 틀린 카드 20문제 뒤 (같은 v24)

- 요청: 몇 번 나오고 몇 번 맞고 틀렸는지 남기기, 틀린 카드는 최소 20문제 뒤에 다시 나오기.
- 기록
  - progress 항목에 `shown`(화면에 나올 때마다), `right`·`wrong`(다시 푼 것까지 모든 답)을 둬요. `logShown`·`logAnswer`는 `entry()`로 쓰기 때문에, 안 본 카드에도 `s: 0`이 들어가 migrate가 지우지 않고 새 카드로 남아요.
  - FSRS 채점은 그대로 세션의 첫 답만 써요. 백업에 함께 담기고, v24부터 세요.
- 화면
  - 답하면 "이 카드: n번 나옴 · 맞힘 · 틀림"이 나와요. 틀리면 "다른 문제 20개 뒤에 다시 나와요"가 붙어요.
  - 관리 → 풀이 기록: 합계(장 수·나온 횟수·맞힘·틀림·정답률)와 많이 틀린 카드 100장.
- 20문제 뒤
  - 세션에 `later`([{ card, at }])와 답 수 `n`을 둬요. 틀리면 at = n + 20이에요. `current()`가 at에 이른 카드를 맨 앞으로 올려요.
  - 묶음(7장)이 바뀌어도 이전 세션의 later·n·saved를 이어받고, 기다리는 카드는 새 묶음에서 빼요(skip).
  - 고를 카드가 더 없으면 기다리는 카드를 바로 내요(작은 덱: 노트·실전 오답·자주 틀린 카드).
  - 모드를 바꾸면 새로 시작해요. 그만두면 기다리던 카드는 FSRS로 다음 날 나와요(틀린 첫 답이라 +1일).
- 근거: 다시 떠올리기 전 간격이 길수록 다시 맞히기는 어렵지만 오래 남아요(지연 효과). 이전에는 묶음 끝, 곧 6문제 안이었어요.
- 테스트
  - 로직: 20개 뒤 재등장·반복 오답, 묶음 사이 이어받기, 기록 함수(migrate 보존).
  - 화면: 48문제 중 틀린 37번 모두 21번째 이후에 다시 나옴, 3장짜리 자주 틀린 카드는 남은 카드가 없을 때 바로 나옴. 콘솔 오류 0.
